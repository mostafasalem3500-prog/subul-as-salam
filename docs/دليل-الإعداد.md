# دليل الإعداد خطوة بخطوة — سُبُل السلام

هذا الدليل مكتوب لتتعلّم وأنت تبني. ستحتاج إلى حسابين مجانيين: **GitHub** للاستضافة، و**Supabase** لقاعدة البيانات والدخول بالإيميل.

> **لماذا Supabase؟** GitHub Pages يستضيف ملفات ثابتة فقط (HTML وCSS وJS)، ولا يشغّل قاعدة بيانات. Supabase قاعدة بيانات PostgreSQL مجانية، ومعها نظام دخول بالإيميل، ويتصل بها الموقع من المتصفح مباشرة. والحماية تتولاها قواعد RLS في الملف `supabase/schema.sql`.

---

## المرحلة 1: جرّب الموقع على جهازك (5 دقائق)

```bash
cd subul
python3 -m http.server 8080
```

افتح `http://localhost:8080`. يعمل الموقع في **وضع التجربة** (الشريط الأصفر أعلى الصفحة):
- البيانات تُحفظ في متصفحك فقط.
- فيه حسابان جاهزان بلا كلمة مرور: المشرف `mushrif@demo.test`، والطالبة `amina@demo.test`.

---

## المرحلة 2: الرفع إلى GitHub Pages

1. أنشئ مستودعًا جديدًا في GitHub، مثلًا `subul-as-salam`. اجعله **Public**، فـ GitHub Pages مجاني للمستودعات العامة.
2. ارفع الملفات بإحدى طريقتين:
   - **من المتصفح:** Add file → Upload files، ثم اسحب محتوى المجلد كله.
   - **من الطرفية:**
     ```bash
     git init && git add . && git commit -m "سبل السلام v1"
     git branch -M main
     git remote add origin https://github.com/<اسمك>/subul-as-salam.git
     git push -u origin main
     ```
3. فعّل النشر: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. افتح تبويب **Actions**؛ ستجد مهمة «Deploy to GitHub Pages» تعمل. عند انتهائها يظهر رابط الموقع، بهذا الشكل:
   `https://<اسمك>.github.io/subul-as-salam/`

**ماذا تفعل هذه المهمة؟** (الملف `.github/workflows/deploy.yml`)
- تنزّل نسخة احتياطية من إسلام هاوس وQuranEnc وHadeethEnc إلى المجلد `data/`.
- تنشر الموقع.
- تتكرر تلقائيًّا كل جمعة، ويمكنك تشغيلها يدويًّا من زر «Run workflow».
- إن أردت كل سور القرآن لكل الترجمات، فعّل الخيار «full» عند التشغيل اليدوي.

> النسخة الاحتياطية تضمن أن يعمل الموقع حتى لو منع متصفح الزائر الاتصال المباشر بالمصدر (CORS) أو تعطّل المصدر مؤقتًا. والنص يُحفظ كما يصل من المصدر، بلا أي تعديل.

## المرحلة 3: قاعدة البيانات (Supabase)

1. ادخل [supabase.com](https://supabase.com)، ثم New project:
   - اختر الاسم `subul`.
   - احفظ كلمة مرور قاعدة البيانات عندك.
   - اختر أقرب منطقة، مثل Frankfurt.
2. افتح **SQL Editor → New query**، والصق محتوى `supabase/schema.sql` كاملًا، ثم اضغط **Run**.
   - يجب أن تظهر «Success».
   - الملف آمن لإعادة التشغيل.
3. أعدّ الدخول من **Authentication → URL Configuration**:
   - **Site URL:** رابط موقعك على GitHub Pages.
   - **Redirect URLs:** الرابط نفسه، وأضف معه `http://localhost:8080` للتجربة.
4. من **Authentication → Providers → Email**، اترك «Confirm email» مفعّلًا. هذا يضمن أن الإيميل حقيقي.
5. خذ المفاتيح من **Project Settings → API**: انسخ `Project URL` و`anon public key`، وضعهما في `assets/js/config.js`:
   ```js
   supabaseUrl: 'https://xxxx.supabase.co',
   supabaseAnonKey: 'eyJhbGciOi...',
   ```
   > مفتاح `anon` مصمّم ليكون علنيًّا في الواجهة، والحماية تأتي من قواعد RLS.
   > **لا تضع أبدًا مفتاح `service_role` في الموقع.**
6. ارفع التعديل إلى GitHub، فيُعاد النشر تلقائيًّا.
7. **اجعل نفسك مديرًا:**
   - سجّل في الموقع بإيميلك.
   - أكّد بريدك من الرسالة التي تصلك.
   - شغّل في SQL Editor:
     ```sql
     update public.profiles set role = 'admin' where email = 'إيميلك';
     ```
   - ستظهر لك صفحة «الإدارة»، ومنها تعتمد طلبات المشرفين.

> **حدود البريد المجاني:** Supabase يرسل عددًا محدودًا من رسائل التأكيد كل ساعة. إذا زاد التسجيل، اربط خدمة بريد (SMTP) من **Authentication → SMTP Settings**، مثل Brevo أو Resend، ولهما خطط مجانية.

## المرحلة 4: كيف يعمل التعليم والمتابعة

### صفحة كل لغة (#/sw · #/rw · #/es)
هي الصفحة الأساسية للغة، ويدخلها الطالب والمشرف والزائر. تجمع:
- المنهج والقرآن والحديث والمكتبة بهذه اللغة.
- ركن الداعية.
- **بنك الرسائل الدعوية** للغة: يكتب رسائله المشرفون من المتحدثين الأصليين، ويذكرون مراجعها، ثم يعتمدها المدير.

الإسبانية فيها كذلك رسائل «رفيق الداعية» الألف، ورابط موقعه الأساسي كما هو.

### ربط المشرف بالطالب عبر الحساب (طلب ثم موافقة)
| الطريقة | الخطوات |
|---|---|
| **رابط الدعوة** (الأسهل) | 1. المشرف ينسخ رابطه من «لوحة المشرف»، مثل `…/#/join/K7Q2M9`، ويرسله بالواتساب.<br>2. الطالب يفتحه، فيسجّل أو يدخل.<br>3. يصل الطلبُ المشرفَ فيضغط «قبول». |
| **الإيميل** | 1. المشرف يكتب إيميل طالب مسجّل.<br>2. تظهر للطالب دعوة في حسابه، فيضغط «قبول». |
| **رمز الإشراف** | 1. الطالب يكتب رمز مشرفه في صفحته الشخصية.<br>2. يصل الطلب المشرفَ فيوافق. |

لا يرى المشرف بيانات الطالب، ولا يراسله، ولا يختبره، إلا بعد الموافقة. والطالب يمكن أن يتابعه أكثر من مشرف.

### صفحة الطالب: أربعة تبويبات يراها الطالب ومشرفه معًا
| التبويب | الطالب | المشرف |
|---|---|---|
| 🧭 **المنهج** | خريطة الـ 12 محطة، وزر «تابع» يأخذه إلى المهمة التالية. | يرى الخريطة نفسها، وتفتح له المحطات بلغة الطالب. |
| 📊 **المتابعة** | نسبة التقدّم، ودرجات كل محطة، والسور المحفوظة، وسجل النشاط. | الشيء نفسه، ويضيف إليه تقييم كل محطة وتوثيق التسميع. |
| 💬 **المحادثات** | محادثة خاصة مع مشرفه، فيها علامة القراءة ✓✓. | الشيء نفسه. التحديث فوري عبر Supabase Realtime، ومعه تحديث احتياطي كل 12 ثانية. |
| 📝 **الاختبارات** | يجيب عن الاختبارات التي يرسلها المشرف، ثم يرى درجته وملاحظة المشرف. | ينشئ اختبارًا للطالب، فيه:<br>- أسئلة اختيار تُصحَّح آليًّا.<br>- أسئلة مكتوبة يصحّحها بنفسه.<br>- موعد اختبار شفهي مع رابط اجتماع. |

**درجة المحطة** هي متوسط ثلاثة أشياء:
- أفضل نتيجة للطالب في اختبار المحطة الآلي.
- تقييم المشرف.
- درجات اختبارات المشرف المربوطة بهذه المحطة.

وتُعدّ المحطة مكتملة في حالتين:
- إذا أنهى الطالب موادها ونجح في الاختبار بـ 80% فأكثر.
- أو إذا اعتمدها المشرف.

> **ترقية قاعدة موجودة:** إذا شغّلت الإصدار الأول من `schema.sql` من قبل، أعد تشغيل الملف كاملًا. سيضيف الجداول الجديدة، والروابط القديمة تبقى مفعّلة.

## المرحلة 5: إضافة محتوى أو لغة

### إضافة مادة من إسلام هاوس إلى محطة
1. ادخل الموقع بحساب مشرف، وافتح «المكتبة». سيظهر بجانب كل مادة رقمها، مثل `#2842635`.
2. ضع الرقم في `assets/js/curriculum.js` داخل المحطة المناسبة:
   ```js
   ih: { sw: [2842635, 2836052], rw: [2837300], es: [] },
   ```

### إضافة لغة
افتح `assets/js/config.js` وفعّل اللغة، أو أضف سطرًا جديدًا، ثم:
- **مفاتيح الترجمة:** خذها من `https://quranenc.com/api/v1/translations/list/<رمز اللغة>`.
- **رمز اللغة في HadeethEnc:** خذه من `https://hadeethenc.com/api/v1/languages`.
- **نصوص الواجهة:** أضف قسمًا بها في `assets/js/i18n.js`.
- **أرقام المواد:** أضفها لكل محطة في `curriculum.js`.

### إضافة كلمات دعوية
أضفها في `assets/js/dawah-words.js`. لكل كلمة شرطان:
- أن تكون مأخوذة كما وردت حرفيًّا في نص ترجمة معتمدة.
- أن يُذكر رقم الآية التي وردت فيها.

**تحديث محتوى «رفيق الداعية»:** ملفاته في `data/rafiq/`. لإعادة استخراجها من مستودع رفيق الداعية بعد أي تحديث:
```bash
npm i acorn
node scripts/import-rafiq.mjs data/rafiq ../rafiq-dawah-es/public/data-*.js
```

```

assets/js/config.js         ← الإعدادات: Supabase واللغات والمصادر
assets/js/curriculum.js     ← المنهج: 12 محطة وأرقام المواد والسور

assets/js/api.js            جلب المحتوى من المصادر (مع ذاكرة ونسخة احتياطية)
assets/js/db.js             قاعدة البيانات: Supabase أو وضع التجربة
assets/js/views/*.js        الصفحات: الطالب، المشرف، القرآن، الحديث، المكتبة، ركن الداعية
assets/css/app.css          الهوية البصرية والحركة
supabase/schema.sql         الجداول والصلاحيات (RLS)
scripts/sync-data.mjs       مزامنة النسخة الاحتياطية من المصادر
data/rafiq/*.json           محتوى «رفيق الداعية» (دروس الداعية، الدليل، المناهج، الرسائل)
.github/workflows/deploy.yml النشر التلقائي
```
